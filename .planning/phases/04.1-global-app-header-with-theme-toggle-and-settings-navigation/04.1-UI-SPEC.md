## Header Variants

Three distinct header variants ship in this phase. All share the same height, border, and background token.

### Variant A — App Header (dashboard and all future app pages)

| Zone | Left | Center | Right |
|------|------|--------|-------|
| Content | App name "Shopping List" (text, 16px semibold) | — | Avatar dropdown (logout) · Settings icon · DarkModeToggle |

- Avatar: 32px circle, initials fallback, triggers DropdownMenu with single item "Log out"
- Settings icon: lucide `Settings`, 20px, ghost button, links to `/household/settings`
- DarkModeToggle: existing component, reused as-is

### Variant B — Settings Header (settings page only)

| Zone | Left | Center | Right |
|------|------|--------|-------|
| Content | Back arrow (`ArrowLeft`, 20px) + "Settings" label (16px semibold) | — | Avatar dropdown (logout) · DarkModeToggle |

- Back arrow: ghost icon button linking to `/dashboard`, 44px min touch target
- Settings icon replaced by back arrow — never both at once
- Avatar dropdown same as Variant A

### Variant C — Minimal Header (onboarding and auth pages)

| Zone | Left | Center | Right |
|------|------|--------|-------|
| Content | — | — | DarkModeToggle only |

- No avatar, no navigation links
- Header bar still renders (replaces fixed top-4 right-4 floating toggle)

### Shared header shell

- Height: 52px (padding: 12px top + bottom, content 28px)
- Background: `bg-background`
- Bottom border: `border-b border-border`
- Horizontal padding: `px-4`
- Layout: `flex items-center justify-between`
- Position: static (not sticky) — consistent with existing dashboard header pattern

## Color

All values reference existing CSS custom properties from `globals.css`. No hardcoded hex values.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` | Header background, page background |
| Secondary (30%) | `bg-card` / `bg-muted` | Dropdown menu surface, avatar fallback background |
| Accent (10%) | `bg-primary` / `text-primary` | — not used in header chrome |
| Destructive | `text-destructive` / `variant="destructive"` | "Log out" confirmation if added in future |
| Border | `border-border` | Header bottom border |
| Foreground | `text-foreground` | Header title text |
| Muted foreground | `text-muted-foreground` | Avatar initials, dropdown secondary text |
| Ghost hover | `hover:bg-accent` | Icon button hover state (via shadcn Button ghost variant) |

Accent reserved for: nothing in this phase — header is intentionally chrome-neutral. Primary accent applies only to avatar role badge (existing settings page pattern, unchanged).

Destructive: "Log out" action in dropdown uses no destructive styling. It is a safe action (user can log back in). No destructive confirmation needed.

Source: `globals.css` token definitions confirmed. Theme-aware via `.dark` class.

## Interaction States

### Avatar dropdown
- Trigger: Avatar button (32px circle)
- Menu items: "Log out" (single item)
- Dropdown placement: bottom-end
- Portal: renders in `<body>` — `.dark` class must propagate (existing known concern in STATE.md)
- Hover: `hover:bg-accent` on menu item
- No loading state needed (logout is instant navigation)

### Settings icon button (Variant A)
- Trigger: click → navigate to `/household/settings`
- Use Next.js `<Link>` wrapped in `<Button asChild variant="ghost" size="icon">`
- Tooltip: none (icon is self-explanatory, label "Settings" accessible via aria-label)
- aria-label: "Settings"

### Back arrow button (Variant B)
- Trigger: click → navigate to `/dashboard`
- Use Next.js `<Link>` wrapped in `<Button asChild variant="ghost" size="icon">`
- aria-label: "Back to dashboard"
- Paired with text label "Settings" (static, not a button) to the right of arrow

### DarkModeToggle (all variants)
- Existing component — no changes to interaction
- Mount guard placeholder `w-8 min-h-[44px]` already implemented

| Error state | N/A — header has no error state |

Note: Logout requires no confirmation. The action is fully reversible (user can log back in). Displaying a confirmation dialog would add friction without safety benefit.

## Accessibility

- All icon-only buttons carry an `aria-label` (specified in Copywriting Contract above)
- Avatar button labeled "Account menu" with dropdown role
- Header landmark: `<header>` element with implicit `role="banner"`
- Keyboard: all interactive elements reachable via Tab in left-to-right order
- Focus ring: `outline-ring/50` from globals.css base layer (already applied)
- Touch targets: 44px minimum on all icon buttons (matches existing `min-h-[44px]` pattern)

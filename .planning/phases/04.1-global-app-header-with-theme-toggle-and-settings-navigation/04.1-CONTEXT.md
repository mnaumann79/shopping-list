# Phase 4.1: Global App Header - Context

**Gathered:** 2026-03-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a consistent `AppHeader` component (avatar → logout dropdown, settings/back nav, DarkModeToggle) to all app pages, and a `MinimalHeader` component (DarkModeToggle only) to auth and onboarding pages. Replace all scattered Phase 4 DarkModeToggle placements with the unified header. No new pages or features — this phase is purely header consolidation.

</domain>

<decisions>
## Implementation Decisions

### User data strategy
- `AppHeader` accepts `userName` as a prop (string) — no client-side session fetch inside the component
- Server component pages fetch session and pass `user.name` to `AppHeader` as prop
- Dashboard page already has `session` in scope — pass `session.user.name` directly
- Settings page: convert from client component to server component so it can fetch session and pass `user.name` the same way

### Header placement
- Per-page: each page renders its own header variant
  - Dashboard → `<AppHeader userName={...} />`
  - Settings → `<AppHeader variant="settings" userName={...} />`
  - Onboarding → `<MinimalHeader />`
  - Auth layout → wrap with `<MinimalHeader />`
- No changes to `(app)/layout.tsx` — header stays at page level

### Phase 4 toggle cleanup
- Remove DarkModeToggle from `ShoppingList` controls bar (Phase 4 placement)
- Remove floating fixed DarkModeToggle from settings and onboarding pages (Phase 4 placement)
- `AppHeader` / `MinimalHeader` become the sole toggle carriers — no duplicate toggles

### Component design
- `AppHeader`: single component with `variant?: "default" | "settings"` prop
  - `"default"`: avatar + settings icon + DarkModeToggle
  - `"settings"`: avatar + back arrow + "Settings" label + DarkModeToggle
- `MinimalHeader`: separate minimal component, DarkModeToggle only
- Both live in `src/components/`
- `LogoutButton` component exists but is a plain ghost button — AppHeader replaces this inline with a DropdownMenu + logout action

### Claude's Discretion
- Exact implementation of the DropdownMenu logout action (can inline the auth signOut call or delegate to a small action helper)
- Whether to keep `LogoutButton` component or remove it (if it becomes unused after this phase)

</decisions>

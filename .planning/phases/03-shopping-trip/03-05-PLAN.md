<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Human verification - Phase 3 shopping-trip success criteria</name>
  <files>none</files>
  <what-built>
    Dashboard shopping-trip experience on the existing `/dashboard` page:
    - Tapping a collapsed row checks or unchecks the item
    - Editing remains available behind an explicit edit control
    - Checked items move into a single completed section that starts collapsed
    - Completed items can be cleared in bulk from a sticky trip action bar with confirmation and undo
    - Store filter chips support `All stores`, remember the last selection, and still include untagged items in filtered views
    - Organization mode can switch between category/aisle, alphabetical, and store sections
  </what-built>
  <how-to-verify>
    Run `npm run dev` and open the dashboard in both desktop and mobile emulation.

    1. Check an active item by tapping its row.
       Expected: item leaves the active list and appears in the collapsed completed section.

    2. Expand the completed section and tap the same item again.
       Expected: item returns to the active list in the correct derived position for the current organization mode.

    3. Open inline edit from the dedicated edit affordance on a collapsed row.
       Expected: edit UI opens without toggling the item checked state.

    4. Switch store filters across `All stores` and at least one named store.
       Expected: named-store view includes matching tagged items plus untagged items; chips remain usable on mobile widths.

    5. Switch organization mode across category, alphabetical, and store.
       Expected: category mode groups by aisle order, alphabetical mode is a single flat A-Z list, store mode renders store sections with a visible untagged section.

    6. Check multiple items, then use clear completed from the sticky trip action bar.
       Expected: confirmation appears, only checked items are removed, and undo restores them during the toast window.

    7. Verify the sticky trip controls and quick-add area on mobile.
       Expected: controls are reachable, do not overlap badly, and do not obscure core content while scrolling.

    Success signal: all 5 Phase 3 roadmap success criteria are met.
  </how-to-verify>

**Modify route.ts** — Replace the sequential SELECT-then-UPDATE with a parallel Promise.all approach. The key insight: instead of using the SELECT results to build the UPDATE WHERE clause (via inArray), the UPDATE uses the same WHERE conditions directly.

Replace the try block content (lines 28-72) with:

```typescript
try {
    const whereConditions = and(
      eq(items.organizationId, orgId),
      eq(items.isActive, true),
      eq(items.isChecked, true)
    );

    // Run SELECT (for storeIds in response) and UPDATE (for soft-delete) in parallel.
    // Both use the same WHERE conditions. The SELECT must JOIN itemStores for storeIds.
    const [rows] = await Promise.all([
      db
        .select({ item: items, storeId: itemStores.storeId })
        .from(items)
        .leftJoin(itemStores, eq(itemStores.itemId, items.id))
        .where(whereConditions),
      db
        .update(items)
        .set({ isActive: false, updatedAt: new Date() })
        .where(whereConditions),
    ]);

    const grouped = new Map<
      string,
      (typeof rows)[number]["item"] & { storeIds: string[] }
    >();

    for (const row of rows) {
      const existing = grouped.get(row.item.id);
      if (existing) {
        if (row.storeId) {
          existing.storeIds.push(row.storeId);
        }
        continue;
      }

      grouped.set(row.item.id, {
        ...row.item,
        storeIds: row.storeId ? [row.storeId] : [],
      });
    }

    const clearedItems = Array.from(grouped.values());
    return Response.json({ clearedItems }, { status: 200 });
  } catch {
    return Response.json({ error: "Failed to clear completed items" }, { status: 500 });
  }
```

Key changes from current code:
- Extracted shared `whereConditions` variable used by both queries
- `Promise.all` runs SELECT and UPDATE concurrently
- Removed the early-return empty check before UPDATE (the UPDATE with no matching rows is a no-op, and the response correctly returns `[]`)
- Removed `.returning()` from the UPDATE call (we don't use its return value)
- The grouping logic for rows into clearedItems with storeIds is unchanged

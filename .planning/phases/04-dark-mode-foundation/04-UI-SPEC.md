## Color

All colors are defined via shadcn/Tailwind semantic CSS custom properties in `globals.css`. Do not use hardcoded hex values in components.

### Light Mode Tokens (`:root`)

| Role | CSS Variable | oklch Value | Usage |
|------|-------------|-------------|-------|
| Dominant (60%) | `--background` | `oklch(1 0 0)` | Page background, main surfaces |
| Secondary (30%) | `--card` / `--secondary` | `oklch(1 0 0)` / `oklch(0.97 0 0)` | Cards, panels, controls bar |
| Accent (10%) | `--primary` | `oklch(0.205 0 0)` | Accent elements only (see below) |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` | Destructive actions only |
| Muted text | `--muted-foreground` | `oklch(0.556 0 0)` | Secondary labels, mode text |

### Dark Mode Tokens (`.dark`)

| Role | CSS Variable | oklch Value | Usage |
|------|-------------|-------------|-------|
| Dominant (60%) | `--background` | `oklch(0.145 0 0)` | Page background, main surfaces |
| Secondary (30%) | `--card` / `--secondary` | `oklch(0.205 0 0)` / `oklch(0.269 0 0)` | Cards, panels, controls bar |
| Accent (10%) | `--primary` | `oklch(0.922 0 0)` | Accent elements only (see below) |
| Destructive | `--destructive` | `oklch(0.704 0.191 22.216)` | Destructive actions only |
| Muted text | `--muted-foreground` | `oklch(0.708 0 0)` | Secondary labels, mode text |

**Accent (`--primary`) reserved for:**
- `DarkModeToggle` button active/focus ring
- Primary action buttons (existing shadcn Button default variant)

Accent is NOT applied to: icon fill, mode label text, border colors, or any surface color.

### Token Audit Requirement

This phase mandates replacing all hardcoded color classes with semantic tokens before any toggle work is considered complete. Components using `bg-white`, `bg-gray-*`, `text-gray-900`, `text-gray-*`, `border-gray-*` must be changed to `bg-background`, `text-foreground`, `border-border` (or the appropriate semantic alternative). No `!important` overrides permitted.

## Component Specifications

### DarkModeToggle

A cycling icon button. One button cycles `system → light → dark` on each click.

| Property | Specification | Source |
|----------|--------------|--------|
| Base component | `Button` variant `ghost` size `icon` from `src/components/ui/button.tsx` | CONTEXT.md |
| Icon — system mode | `Monitor` from Lucide | CONTEXT.md |
| Icon — light mode | `Sun` from Lucide | CONTEXT.md |
| Icon — dark mode | `Moon` from Lucide | CONTEXT.md |
| Icon size | 16px (`size-4`) | Default for icon button |
| Button size | 36px visual, `min-h-[44px]` touch target | Touch target standard |
| Mobile display | Icon only | CONTEXT.md |
| Desktop display | Icon + mode label text (e.g. "System", "Light", "Dark") | CONTEXT.md |
| Tooltip | Current mode name on hover (both breakpoints) | CONTEXT.md |
| Mount guard | Render `<div className="w-8 h-8" />` placeholder until mounted — prevents hydration mismatch | PITFALLS.md |

**Placement:**
| Page | Position | Notes |
|------|----------|-------|
| Dashboard (`ShoppingList.tsx` controls bar) | Top-right of controls bar, alongside store filter and org mode controls | CONTEXT.md |
| Settings page | Floating top-right corner | CONTEXT.md |
| Onboarding page | Floating top-right corner | CONTEXT.md |

**Theme cycle order:** System → Light → Dark → System (wraps)

**Transition:** Apply `transition-colors duration-150` scoped to `background-color` and `color` on the `<html>` element via CSS. Do NOT use `transition: all`. Declare in `globals.css`:

```css
html {
  transition: background-color 150ms ease, color 150ms ease;
}
```

### Sonner Toaster

Pass `theme={resolvedTheme as 'light' | 'dark' | 'system'}` from `useTheme()` to `<Toaster />` in `layout.tsx`. This ensures toast notifications match the active theme. Source: PITFALLS.md integration gotchas.

### Shadcn Dropdown Portals

Shadcn dropdown menus render in a portal (outside the `<html>` tree root). The `@custom-variant dark (&:is(.dark *))` selector propagates to portaled elements because portals append to `document.body`, which is a descendant of `<html class="dark">`. Verify during implementation that store filter and sort dropdowns render with correct dark backgrounds. If they do not, add `className="dark"` to the portal container explicitly.

## Interaction States

### DarkModeToggle Button

| State | Visual |
|-------|--------|
| Default | Ghost button, icon at current theme color (`text-foreground`) |
| Hover | `bg-accent` fill (shadcn ghost hover — automatic) |
| Focus | `ring-2 ring-ring` (shadcn default focus ring) |
| Active/Press | `bg-accent/80` (shadcn ghost active — automatic) |
| Pre-mount | Invisible placeholder `div` with `w-8 h-8` — no flash, no layout shift |

### Theme Transition

| Trigger | Behavior |
|---------|----------|
| Button click | 150ms `background-color` + `color` fade on `<html>` — no full re-render |
| Page load (stored preference) | next-themes inline blocking script applies theme before paint — no FOUC |
| OS preference change (system mode) | `prefers-color-scheme` listener updates immediately via next-themes `enableSystem` |

## Implementation Checklist (for Executor)

These are the visual contracts that must hold after implementation:

- [ ] `DarkModeToggle` renders `Monitor` / `Sun` / `Moon` icon matching the active resolved theme
- [ ] `DarkModeToggle` shows mode label text on desktop (`sm:` breakpoint), icon only on mobile
- [ ] `DarkModeToggle` renders an invisible placeholder of identical dimensions before mount (no layout shift)
- [ ] Tooltip shows current mode name on hover at both breakpoints
- [ ] 150ms `background-color` + `color` transition fires on theme switch — no `transition: all`
- [ ] No FOUC on hard refresh in dark mode (blocking script via next-themes is active)
- [ ] All app pages render without hardcoded `bg-white` or `text-gray-*` visible in dark mode
- [ ] Shadcn dropdowns (store filter, sort) render correct dark background when `.dark` is active
- [ ] Sonner toasts match active theme (dark toast in dark mode, light toast in light mode)
- [ ] Theme persists across browser tab close and reopen
- [ ] System preference mode responds live to OS appearance changes

# Roadmap: Household Shopping List App

## Overview

Two milestones delivering a complete household shopping list app. v1.0 establishes authentication, household setup, and the core list. v1.1 adds dark mode, visual polish, and theme customization.

## Milestones

- [x] **v1.0** - Foundation, Core List, Shopping Trip (completed 2026-03-17)
- [x] **v1.1** - Dark Mode, Global Header, Visual Polish, Theme Preview (completed 2026-03-23)

## v1.0 Milestone

Three phases delivering the core shared list experience.

- [x] **Phase 1: Foundation** - Authenticated users and household setup with member invites (completed 2026-03-12)
- [x] **Phase 2: Core List** - Item CRUD, categories, and per-item store tags (completed 2026-03-13)

## Phase Details

### Phase 1: Foundation
**Goal**: Household members can create accounts, form a household, and invite each other to share the same list context
**Depends on**: Nothing (first phase)
**Requirements**: AUTH-01, AUTH-02, AUTH-03, AUTH-04, HSHD-01, HSHD-02, HSHD-03, HSHD-04
**Success Criteria** (what must be TRUE):
  1. User can sign up with email and password, then log in and stay logged in across browser refreshes and tab closes
  2. User can log out from any page and is immediately redirected away from protected content
  3. User can create a household during the signup/onboarding flow
  4. Household admin can invite a new member by email and that member can join via the invite link
  5. Household admin can generate a shareable join link that any new user can use to join the household
**Plans**: 8 plans

Plans:
- [x] 01-01-PLAN.md - Test infrastructure: Vitest + Playwright configs and all E2E stub files
- [x] 01-02-PLAN.md - Project bootstrap: Next.js init, all dependencies, full Drizzle schema (all phases)
- [x] 01-03-PLAN.md - better-auth config: server instance, API handler, middleware, auth-client
- [x] 01-04-PLAN.md - Auth UI: sign-up, sign-in, onboarding, app layout, household switcher, logout
- [x] 01-05-PLAN.md - Email invite: React Email template, invite API, accept-invite page
- [x] 01-06-PLAN.md - Shareable join link: join-links API, join/consume API, /join page
- [x] 01-07-PLAN.md - Household settings: email invite form, join link UI, member list with remove
- [x] 01-08-PLAN.md - Verification: full test suite + human sign-off on all 5 success criteria

### Phase 2: Core List
**Goal**: Household members can build and maintain a shared grocery list with items organized by category and tagged to specific stores
**Depends on**: Phase 1
**Requirements**: ITEM-01, ITEM-02, ITEM-03, CAT-01, CAT-02, CAT-03, STOR-01, STOR-02, STOR-03
**Success Criteria** (what must be TRUE):
  1. User can add an item with a name, optional quantity, optional note, category assignment, and one or more store tags
  2. User can edit any field on an existing item (name, quantity, note, category, store tags)
  3. User can delete an item from the list
  4. List displays a default set of grocery categories (produce, dairy, bakery, meat, frozen, pantry, beverages, household, personal care, other) and user can create custom categories
  5. User can add and manage stores (add, rename, delete) that items can be tagged to
**Plans**: 8 plans

Plans:
- [x] 02-01-PLAN.md - Wave 0: test stubs (RED state) + categories unique constraint migration
- [x] 02-02-PLAN.md - Store API routes: GET/POST /api/stores and PATCH/DELETE /api/stores/[id]
- [x] 02-03-PLAN.md - Category lib: ensureDefaultCategories + fetchCategories + GET/POST /api/categories
- [x] 02-04-PLAN.md - Item API routes: GET/POST /api/items and PATCH/DELETE /api/items/[id]
- [x] 02-05-PLAN.md - Store management UI: StoresSection added to household settings page
- [x] 02-06-PLAN.md - Shopping list structure: ShoppingList, CategorySection, QuickAddBar components
- [x] 02-07-PLAN.md - ItemRow: collapsed view, inline expand, swipe-to-delete, undo toast
- [x] 02-08-PLAN.md - Dashboard wiring + human verification of all 5 Phase 2 success criteria

### Phase 3: Shopping Trip
**Goal**: Household members can efficiently complete a shopping trip using the list - checking off items, filtering by store, and viewing items organized for fast in-store navigation
**Depends on**: Phase 2
**Requirements**: ITEM-04, ITEM-05, ITEM-06, ORG-01, ORG-02, ORG-03, ORG-04
**Success Criteria** (what must be TRUE):
  1. User can check off an item during a shopping trip and uncheck it if checked by mistake
  2. User can clear all checked items from the list at once after a trip completes
  3. User can filter the list to show only items tagged to a selected store, enabling focused single-store shopping
  4. User can view items grouped by category/aisle for efficient in-store navigation
  5. User can sort the list alphabetically or by store
**Plans**: 5 plans

Plans:
- [x] 03-01-PLAN.md - Wave 0 test scaffolding for check/uncheck, bulk clear, selectors, and trip E2E
- [x] 03-02-PLAN.md - API updates for `isChecked` and bulk clear + `ShoppingList` selector/state refactor
- [x] 03-03-PLAN.md - `ItemRow` trip interaction redesign to resolve tap-to-toggle vs edit
- [x] 03-04-PLAN.md - Store chips, organization controls, completed section, and sticky clear-completed UI
- [x] 03-05-PLAN.md - Automated/manual verification and roadmap/state updates after approval

### Phase 4: Dark Mode Foundation
**Goal**: User can toggle between System, Light, and Dark themes with preference persisted across sessions
**Depends on**: Phase 3
**Requirements**: DARK-01, DARK-02, DARK-03, DARK-04, VIS-03
**Success Criteria**:
  1. Theme toggle cycles through System → Light → Dark → System
  2. Selected theme persists across browser sessions via localStorage
  3. No flash of incorrect theme on page load (theme applied before first paint)
  4. All UI uses semantic color tokens consistently

### Phase 4.1: Global App Header
**Goal**: All app pages display a consistent header with avatar, settings navigation, and theme toggle
**Depends on**: Phase 4
**Requirements**: HDR-01, HDR-02, HDR-03
**Success Criteria**:
  1. Dashboard and settings pages show header with avatar dropdown and theme toggle
  2. Avatar dropdown provides logout action accessible from any app page
  3. Settings page header shows back navigation; auth pages show theme toggle only

### Phase 5: Compact Item Row
**Goal**: Shopping list items display as compact single-line rows
**Depends on**: Phase 4.1
**Requirements**: VIS-01, VIS-02
**Success Criteria**:
  1. Item row shows name, quantity, store tag, and notes preview in a single line
  2. Row height is consistent between checked and unchecked states

### Phase 6: Store Default Persistence
**Goal**: Quick add form remembers the last selected store
**Depends on**: Phase 5
**Requirements**: DEF-01
**Success Criteria**:
  1. Store selector in quick add defaults to the last store the user selected

### Phase 7: Visual Design System
**Goal**: Formalize color tokens, typography, and interaction states across the app
**Depends on**: Phase 6
**Requirements**: VIS-03 (unified semantic color tokens)
**Success Criteria**:
  1. All TSX files use semantic color tokens (no hardcoded color classes)
  2. Store abbreviations display as pill chips with bg-accent
  3. Hover/focus states use consistent token pattern
  4. WCAG AA contrast ratio (4.5:1) verified for all text

### Phase 8: Theme Preview
**Goal**: User can preview three theme palettes before applying
**Depends on**: Phase 7
**Success Criteria**:
  1. Settings page shows Clean & Fresh, Bold & Playful, and Warm Palette previews
  2. Each palette has light and dark mode variants
  3. Theme preview persists in localStorage and loads on app startup

# Milestone v1.1: Design Polish

**Status:** ✅ SHIPPED 2026-03-23
**Phases:** 4-8
**Total Plans:** 8

## Overview

Improve usability and visual consistency across the app — dark mode, compact list rows, unified color tokens, smart store defaults, and theme preview palettes.

## Phases

### Phase 4: Dark Mode Foundation

**Goal**: Users can switch between System, Light, and Dark themes — preference persists, page loads without a flash of wrong theme, and all app pages render consistently in both themes
**Depends on**: Phase 3 (v1.0 complete)
**Requirements**: DARK-01, DARK-02, DARK-03, DARK-04, VIS-03
**Plans**: 2 plans

Plans:

- [x] 04-01-PLAN.md — Wire ThemeProvider, FOUC prevention, themed Toaster, transition CSS, color token audit (completed 2026-03-18)
- [x] 04-02-PLAN.md — Build DarkModeToggle component and place on all pages (completed 2026-03-18)

**Details:** Three-state theme toggle (System/Light/Dark) placed consistently across all pages. Theme preference persists in localStorage. FOUC prevented via ThemeProvider mount guard.

### Phase 04.2: Visual Design System Audit (MERGED)

**Status:** Merged into Phase 7. The color audit, typography formalization, and accessibility work from this phase was completed as part of Phase 7.

### Phase 4.1: Global App Header (INSERTED)

**Goal:** Every app page has a consistent header showing the user's avatar, a settings link, and the theme toggle — with logout accessible from the avatar; settings link replaced by a back arrow on the settings page, and hidden on onboarding/auth pages
**Depends on:** Phase 4
**Requirements**: DARK-04, HDR-01, HDR-02, HDR-03
**Plans:** 2/2 plans complete

**Header behavior by page:**
- All app pages: avatar (→ logout), settings link, theme toggle
- Settings page: avatar (→ logout), back arrow (instead of settings link), theme toggle
- Onboarding / auth pages: theme toggle only

Plans:

- [x] 04.1-01-PLAN.md — Create AppHeader and MinimalHeader components with tests (completed 2026-03-18)

### Phase 5: Compact Item Row

**Goal**: Shopping list items display as compact single-line rows so users can scan a long list quickly during a store trip
**Depends on**: Phase 4
**Requirements**: VIS-01, VIS-02
**Plans**: 1 plan

Plans:

- [x] 05-01-PLAN.md — Rewrite ItemRow as compact single-line row with Dialog edit modal, update tests (completed 2026-03-19)

### Phase 6: Store Default Persistence

**Goal**: The add-item form automatically pre-selects the last-used store so users adding multiple items during a shopping trip do not need to re-select the store on every item
**Depends on**: Phase 4
**Requirements**: DEF-01
**Plans**: 1 plan

Plans:

### Phase 7: 4.2 Visual Design System

**Goal**: All app pages use unified semantic color tokens (no hardcoded color classes), store abbreviations render as pill chips, icon buttons have formal hover/focus states, and the design system is documented

**Goal:** Add three theme preview palettes to settings — Warm & Inviting (terracotta/sage), Clean & Fresh (green/blueberry), and Bold & Playful (coral/teal) — each with dark mode variants, persisted to localStorage so selection survives refresh

## Milestone Summary

**Decimal Phases:**
- Phase 4.1: Global App Header (inserted after Phase 4 for persistent navigation)

**Key Decisions:**

- Three-state theme toggle (System/Light/Dark) — not a binary light/dark switch
- Post-mount preference restore — SSR-safe defaults, then reconcile persisted UI in effects
- VIS-03 (unified color tokens) ships with Phase 4 — prerequisite for verifiable dark mode
- Dialog controlled by isEditing state — sibling buttons for row body and pencil to avoid nested button HTML
- Cascading defaults: filter store (Priority 1), last-used localStorage (Priority 2), blank (Priority 3)
- Pill chip pattern: `bg-accent rounded-full px-1.5 py-0.5 text-[10px] font-medium`
- Icon button focus pattern: `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring`

**Issues Resolved:**
- FOUC flash of wrong theme on page load
- Nested button HTML invalid structure
- Hardcoded color classes throughout codebase
- Layout shift when checking items (consistent row height)

**Technical Debt Incurred:**
- Phase 04.2 merged into Phase 7 (scope creep absorbed)
- Notes modal feature added post-UAT (ItemRow enhancement)
